# 学习活动热力图 · 版式规格

来源：用户给的设计参考稿（621×303 PNG）+ 真机量测。所有值都是**相对格径的比例**，
换机型、换周数都不会走样。

## 几何

| 项 | 参考稿实测 | 比例 | 本项目实现 |
|---|---|---|---|
| 格径 | 33 px | 1.00 | 由 `LayoutBuilder` 解方程算出（411dp 屏上 ≈ **19.43 dp**） |
| 列间隙 | 6 px | **0.18 × 格径** | 同（≈ 3.5 dp） |
| 行间隙 | 5–6 px | 同上 | 同 |
| 圆角 | 5.6 px | **0.17 × 格径** | 同（≈ 3.3 dp） |
| 形状 | 33 × 34 px | 近方形 | 正方形（强制 `width == height`） |
| 星期标签列 | 40 px（含间隙） | 0.075 × 网格宽 | 16 dp 标签 + 6 dp 间隙 |
| 图例色块 | 19 px | 0.58 × 格径 | 11 dp（定值） |

**验算**：参考稿 格径/网格宽 = 33/535 = **6.17%**；本项目 19.43/317.4 = **6.12%** —— 比例吻合。

## 配色（四档，取自参考稿图例）

| 档 | 值 | 含义 | 色值 |
|---|---|---|---|
| 0 | `v == 0` | 没学 | `#EEF1F8` |
| 1 | `0 < v` | 学了 | `#C7D4F8` |
| 2 | `v ≥ 50% × 目标` | 过半 | `#8FA9F5` |
| 3 | `v ≥ 目标` | 达标 | `#4F6DF5` |

> 参考稿的图例经像素扫描确认是 **4 个色块**（少 ▢▢▢▢ 多），不是 5 个。
> 色块位置 x = 471 / 497 / 524 / 550，间距 26.5，块宽 19。

## 版式

- 标题行：`学习活动`（15/w800）在左，`近 N 周`（12/w600/`inkSoft`）在右
- 图例**靠右下**（参考稿如此；旧实现是左下）
- 标题 → 网格：14 dp；网格 → 图例：12 dp

## 两条必须守住的规矩（都踩过）

1. **格子必须给明确宽高。**
   旧实现 `Container(margin:…, decoration:…)` 塞进 `Row(spaceBetween)`，
   既没 child 也没 width → 固有宽度 0 → 126 格全画不出来，
   真机实测该区域非白像素 = **0**。现在用 `SizedBox` 显式定尺寸。
   `test/heatmap_card_test.dart` 第 ① 条钉着这条。

2. **列必须对齐到周一。**
   旧实现取"最近 126 天"顺序切成 7 天一列 → 每列首格是任意星期几，
   左侧 `一/三/五/日` 标签就成了**假信息**。
   正确：先把末列对齐到本周日，再往前推 N 周，首列必然是周一。

## 分档基准：用「每日目标」，不用「历史最大值」

旧实现 `ratio = v / max`（max = 历史单日最大量）。某天一旦爆量（复习日刷 60 个），
其余天全部落进最低档、整张图发白 —— 量化分档的经典坑。
改用每日目标后语义也更清楚：**用户能读出"哪天达标了"**，而不只是"哪天相对多"。

## 未来日期

`date.isAfter(today)` → 一律第 0 档。
正常数据不会有未来记录（`studyLog` 只写当天），但时钟回拨/脏数据时不该冒出
"未来已经学过"的格子。
